## 1. The page (Admin -> Provider Sync)
- **Status bar:** state (running / healthy / needs attention / failed / off), last successful catalog check, last successful price update, target interval, actual interval (target vs. measured provider fetch time), next check, item being processed, one **CHECK NOW** button (one provider fetch serves both functions), progress bar + stop.
- **A - Check provider catalog changes:** tiles for new products, new durations, removed products/durations detected (current + 24 h), items awaiting manual import, variants disabled after confirmed removal, mapping conflicts; button to the **New Provider Products** page (still in the admin menu with a badge). **No import button on this page.**
- **B - Automatic price sync:** tiles for variants monitored, prices checked (last cycle), increased / decreased (24 h), unchanged, INR costs recalculated, failed price checks, last price update; collapsible settings (auto on/off, target interval, USD->INR rate, provider currency, follow provider price, protect my edited prices).
- **Logs (tabs):** PRICE CHANGES (product, duration, variant id, V1/V2, provider old -> new + currency + rate, INR cost old -> new, selling price old -> new, result), CATALOG CHANGES (new / removed / renamed / id change / imports with old+new data), NEEDS REVIEW (conflicts, unusable entries, restore of archived products), ERRORS.
- Removed from the page (server logic kept): repair, merge-duplicates, removal mode, manage-manual, API-version policy, category rules/default. `save_settings` is now partial, so these stored settings are never reset.

## 2. Backend (`includes/provider_sync.php`, `api/admin/provider-sync.php`)
- **New products / new durations:** unknown provider ids are queued in `provider_pending_products` with `kind` = `new_product` or `new_variant` (new duration of a product the store already has; target product shown). Status text: NEW - AWAITING MANUAL IMPORT. Nothing is created automatically. New manual path **ADD DURATION TO MY PRODUCT** (preview re-verifies with a fresh catalog; confirm re-verifies again; one transaction; duplicate duration name / mapped id / wrong parent blocked; active or disabled; same go-live rules).
- **Removals:** only after a fully fetched, non-empty catalog; exact variant id match; mass-removal guard kept; the variant is **disabled** (`sync_removed=1`), the product only when no enabled variant remains; `delete_if_no_orders` is neutralised (nothing is deleted automatically). Hand-made products mapped to a provider id are now also covered by exact-id removal (before: price only). A vanished id + new id with the same name is still not re-mapped (conflict warning). Audit: `sync_logs` (`removed_disabled`, old data + reason).
- **Prices:** `product_plans.inr_cost` (new column) holds the converted INR cost separately from `price` (selling price); `provider_price_history` (new table; separate from `price_changes`, so no customer notices) records every provider price event with direction (up / down / set / recalc) and whether the selling price was actually changed (protected prices are kept, cost still recorded). 0 / missing / invalid / unsupported currency never overwrite. Counters: up, down, INR recalculated, failed requests, invalid prices. New settings written: `sync_last_catalog_ok`, `sync_last_price_update`, `sync_last_fetch_ms`, `sync_last_cycle`.
- Pending products never make a price sync "incomplete"; invalid provider prices, unusable entries, failed rows and failed pages do.

## 3. Limits / decisions to check
- Provider rate limit unknown; every cycle makes >= 1 catalog request (6/min per page at 10 s). "Actual interval" = max(target, last fetch time + 1 s); `Retry-After` is not parsed. The cron worker (`* * * * * php cron/provider_sync.php --loop`) must be installed for background operation; that cannot be verified here.
- Providers' real catalog field names are unconfirmed (`php tools/audit_catalog.php --raw`); parent/duration grouping, and therefore `new_variant` detection, depends on them.
- "Removed products detected" counts products marked removed; "24 h" figures come from the logs.
- Interactions: removal of hand-made mapped variants and the default of protecting nothing (`PROTECT PRICES I EDITED MYSELF` = NO) mean the provider price replaces hand-set selling prices on change; switch protection ON if you use markups.
- v43-v49 `mirror_*` scripts describe old auto-create behaviour and are obsolete.
